DETERMINISTIC SOFTWARE FORENSICS

Give reasoning systems
facts worth reasoning from.

Apollo Command Module separates mechanical evidence gathering from engineering judgment. Python and conventional debugging tools establish bounded, reproducible facts; humans and AI systems can spend their attention on interpretation, hypotheses, and decisions.

Quick start View source
session capture
$ python3 apollo.py session capture \
    --application example-application \
    --executable /opt/example/bin/application \
    --output ./apollo-session-001

# reproduce the behavior, then verify offline:
$ python3 apollo.py session verify --session ./apollo-session-001

THE WORKFLOW

Capture once. Inspect repeatedly.

01

Authorize

Define exactly which application Apollo may launch on the current machine.

02

Capture

Run the application under bounded session supervision and reproduce the behavior.

03

Preserve

Record provenance, lifecycle state, runtime output, debugger state, and crash evidence when applicable.

04

Verify

Check bundle structure, hashes, sizes, semantics, and consistency without rerunning the application.

CAPABILITIES

A small command layer for reproducible engineering.

Session capture

Supervise an authorized Linux application while retaining bounded runtime and debugger evidence.

Crash evidence

Automatically collect bounded fatal-signal, thread, stack, register, module, and disassembly evidence.

Offline verification

Verify an existing session bundle without launching the captured application again.

Source & trace facts

Extract source regions, cross-reference text, compare structured traces, inspect patches, and run bounded probes.

Deterministic firstPrefer inspectable facts over narrative claims.
Bounded captureAvoid unrestricted dumps and unbounded diagnostic output.
Explicit provenanceRecord executable identity and session metadata instead of guessing.
AI independentEvidence should remain useful no matter which reasoning system consumes it.
